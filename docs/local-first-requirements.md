# ローカルファースト版 報告書アプリ仕様

作成日: 2026-06-10

## 1. 目的

本アプリは、在宅医療を行う薬剤師が、居宅療養管理指導報告書を速く正確に作成し、医療機関およびケアマネ/介護事業所へ送付するための業務アプリである。

初期版は自薬局内利用を主目的としつつ、他薬局へ横展開できる配布形態を前提にする。

## 2. 基本構成

- 本体はWindowsローカルアプリとする。
- Vercelは入口、配布ページ、更新案内、マニュアル、導入コード入力画面を担当する。
- 利用者はVercelアカウントへログインしない。
- 既存Reactアプリを土台に大改修する。
- データの正本はローカルPC内DBとする。
- 初期版では1薬局1台を正本PCとする。
- 将来、クラウド同期やクラウドバックアップを拡張できる設計にする。ただし初期版のアプリ本体はローカルDB専用とする。

## 3. 初期版でやらないこと

- アプリからの直接FAX送信
- 複数PC同期
- クラウドDBを正本にする運用
- 利用者別の細かい権限制御
- バーコード/在庫連携
- HOT/JAN連携

## 4. 導入と起動

- 初回導入はVercelのURLから行う。
- Vercel入口で導入コードを入力し、Windows版インストーラーをダウンロードする。
- Windowsローカルアプリはインストーラー形式で配布する。
- 初回はセットアップ画面を表示し、普段は常駐に近い形で動作する。
- 日常利用はWindowsアプリのデスクトップショートカットから開始する。Vercel URLは初回導入、更新案内、接続確認の補助入口とする。
- ネットがない患者宅ではWindowsアプリからローカル機能を利用できる。
- PC再起動時はWindowsログイン後にローカルアプリを自動起動し、ローカルDB、ローカルAPI、AI環境の状態を確認する。

## 5. 認証とロック

- Vercelの管理アカウントは開発者/管理者だけが使い、利用者には共有しない。
- 導入コードは初回導入/初回有効化のために使う。毎回入力しない。
- 導入コードはVercel側の管理表で発行、失効、利用台数を管理できるようにする。
- 日常利用はローカルPINで保護する。
- 15分無操作でロックし、再開時にPINを入力する。
- アプリをダウンロードできる時点で利用許可済みとみなし、初期版では利用者別AI権限制御はしない。

## 6. データ保存

- ローカルDBを正本とする。候補はSQLite。
- 患者、報告書、薬剤リスト、関係機関、薬局設定、定型文、設定情報を保存する。
- 報告書は作成時点の患者情報、宛先、報告元、薬剤情報、計算結果をスナップショット保存する。
- 報告元には薬局名、薬局住所、TEL、FAX、担当薬剤師名を含める。
- 年齢は訪問日時点で計算し、報告書スナップショットに保存する。再印刷時に現在年齢で再計算しない。
- 患者マスタ変更後も過去報告書の内容は変わらない。
- 報告書作成画面で患者情報や宛先を修正した場合、保存時に以下を選べる。
  - 今回の報告書だけ変更
  - 患者マスタにも反映
  - キャンセル
- 患者、報告書の削除は論理削除のみとする。`deleted_at` を持たせ、復元可能にする。

## 7. バックアップ

- 毎日1回、自動バックアップを作成する。
- 手動の「今すぐバックアップ」も用意する。
- アップデート前は自動でバックアップする。
- 標準ではPC内に暗号化バックアップを保存する。
- 任意設定で、Google Drive for desktop の同期フォルダにも暗号化バックアップをコピーする。
- Googleドライブは使用者が設定した場合だけ使う。
- 復元にはパスワードまたは薬局キーを要求する。
- 薬局キーはPC内だけに置かず、導入管理者側で薬局ごとに台帳管理できるようにする。
- バックアップは稼働中のSQLiteファイルを直接圧縮しない。SQLite backup API または `VACUUM INTO` 相当の安全なDBエクスポートを使う。
- 稼働中DB本体の保護は別途必要とする。初期導入要件としてBitLocker有効化を推奨し、技術選定でSQLCipher採用も検討する。
- 訪問メモは報告書スナップショットに含め、暗号化バックアップ対象に含める。

## 8. 患者マスタ

必須項目:

- 氏名
- 生年月日
- 性別
- 医療機関
- 主治医

任意項目:

- 住所
- 連絡先
- 家族連絡先
- ケアマネ/居宅介護支援事業所
- 訪問看護ステーション
- 薬局関連情報
- メモ

ケアマネが未登録でも患者登録できる。ケアマネ向け出力時に未登録なら警告し、今回報告書だけ一時入力できる。

## 9. 関係機関マスタ

以下を管理する。

- 医療機関
- 居宅介護支援事業所
- 訪問看護ステーション
- 薬局

初期版の報告書宛先としては、医療機関と居宅介護支援事業所を主に使う。

## 10. 報告書作成フロー

- 主動線は、患者一覧から患者を選び、前回情報を引き継いで新規報告書を作成する流れとする。
- 前回情報の取得対象は、作成日時ではなく訪問日が最も新しい報告書とする。同一訪問日の報告書が複数ある場合は、作成日時が新しいものを使う。
- 前回報告書から自動引き継ぎする情報は、固定情報と薬剤リストまでとする。
- 指導内容、主訴等、その他伝達事項など今回評価にあたる本文は自動コピーしない。
- 画面はタブ/セクション分けとする。
  - 基本情報
  - 状況確認
  - 薬剤管理
  - 指導内容
  - 次回予定/申し送り
  - 印刷確認
- 保存は自動保存と手動保存の両方を用意する。
- 保存状態を表示する。
  - 保存中
  - 保存済み
  - 未保存あり
  - 保存失敗

## 11. 既存帳票項目

既存レポート様式にある項目は削らない。項目名も基本そのまま維持する。

削らない項目:

- 報告先
- 報告元
- 患者氏名、生年月日、年齢、性別
- 医療機関
- 処方医
- 訪問日
- 処方日
- 調剤日
- 指導を受けた人
- 服薬状況
- 保管状況
- 他科受診
- 併用薬
- アレルギー/副作用歴
- 相互作用
- 主訴等
- 服薬指導内容
- その他伝達事項
- 次回訪問予定日
- 定期薬の「最短でいつまで分」
- 定期薬リスト
- その他薬剤リスト

A4 1枚に収めるため、配置や行間は調整してよい。ただし項目の自動省略はしない。

## 12. 帳票出力

- 提出先は医療機関とケアマネ/介護事業所とする。
- フォーマットと本文は共通にする。
- 内容は同じで、宛名とFAX番号だけ変えた2通を出力する。
- 片方だけ印刷/出力も可能にする。
- 2通まとめて印刷も可能にする。
- 初期版は印刷/PDF出力までとし、FAX送信は既存のFAX機/複合機で行う。
- A4 1枚を原則とする。
- 薬剤情報など削れない情報で超過する場合は2枚目を許可する。
- 文字を潰して読みにくくしない。
- 印刷前に「2枚になります」と分かるようにする。
- PDF保存は任意とする。DBには入力データを保存し、必要時に再生成する。

## 13. 薬剤マスタ

- 正本は支払基金の医薬品マスターとする。
- 初期版で使う項目は以下に絞る。
  - 薬剤名
  - カナ名/検索用文字列
  - 単位
- 薬価、後発品区分、経過措置、メーカー名、HOT/JANは初期版では使わない。
- マスタ外薬剤は自由入力できる。
- 自由入力した薬剤も患者ごとの薬剤リストには保存する。
- 2026-06-10時点で、`src/data/y_ALL20260522.csv` を配置済み。
- マスター更新はアプリ内の「薬剤マスタ更新」から行えるようにする。
- 支払基金CSVはShift_JIS/CP932として読み込む。
- 検索用に薬剤名、カナ名を正規化する。全角/半角、長音、大小かな、スペース差異を吸収する。

## 14. 薬剤区分

薬剤は2分類とする。

### 定期薬

- 毎日または決まった間隔で継続使用する薬。
- 「いつまで分」計算対象。
- 画面では薬剤ごとの「いつまで分」を表示する。
- 帳票では薬剤ごとの「いつまで分」は表示しない。
- 帳票には定期薬全体の「最短で○月○日まで分」を1箇所表示する。

### その他薬剤

- 抗生剤などの短期薬、頓服、外用、保管薬、予備薬など。
- 患者の薬剤リストには入れる。
- 定期薬の「いつまで分」計算には入れない。
- 入力項目は薬剤名、数量、単位、備考とする。
- 備考には期限や特記事項を書く。
- 帳票には薬剤名、数量/単位、備考を1行ずつ短く表示する。

## 15. 定期薬の残薬計算

用語は「確保日」ではなく「いつまで分」に統一する。

計算基準:

- 訪問日を1日目として数える。
- 例: 2026-06-10に28日分ある場合、2026-07-07まで分。
- 計算式は `訪問日 + 合計日数 - 1日`。

今回処方日数:

- 報告書全体の標準処方日数を入力し、薬剤ごとに上書き可能にする。
- 14日、21日、28日をクイック選択にする。
- 任意の日数も手入力できる。

残薬計算:

- 前回値は定期薬全体の最短日ではなく、薬剤ごとの前回「いつまで分」を引き継ぐ。
- 薬剤ごとに、前回「いつまで分」から今回訪問日までに経過した日数を差し引く。
- 薬剤ごとに、今回処方日数を足す。
- 薬剤ごとに今回の合計残日数を計算する。
- 薬剤ごとに「いつまで分」を計算する。
- 薬剤が前回報告書に存在しない場合は前回残0日として扱う。
- 定期薬の中で最も早い日付を、定期薬全体の最短「いつまで分」とする。
- 薬剤ごとの前回「いつまで分」が今回訪問日より前の場合、その薬剤の前回残は0日として扱い、今回処方日数だけで計算する。
- 薬剤ごとの前回「いつまで分」が未登録の場合も、その薬剤の前回残は0日として扱い、今回処方日数だけで計算する。
- 患者宅で実際に数えた残薬が計算値と違う場合、薬剤ごとに「実残日数で上書き」できる。
- 実残日数で上書きした薬剤は、今回の合計残日数と「いつまで分」を上書き値から再計算する。
- 実残日数上書きには、任意で理由メモを残せる。

帳票表示:

- 定期薬ごとの帳票表示は、薬剤名 + 今回の合計残日数とする。
- 帳票の別の1箇所に、定期薬全体の最短「いつまで分」を表示する。
- 表示例: `定期薬は今回調整後、最短で2026年7月12日まで分を確認しています。`

## 16. 定型文

- 定型文は薬局全体で共通にする。
- ローカルDBに保存する。
- バックアップ対象に含める。
- 初期版では利用者別お気に入りは持たない。
- 定型文を用意する項目:
  - 服薬状況
  - 保管状況
  - 主訴等
  - 服薬指導内容
  - その他伝達事項
- 入力画面で定型文を選択し、追記/置換できる。
- チェック項目入力は初期版では入れない。

## 17. AIモード

AIは補助機能であり、AIなしでも通常の報告書作成、保存、印刷は使える。

基本仕様:

- AIモードはオン/オフ切り替え可能にする。
- オフ時は通常の手入力アプリとして動く。
- オン時だけ訪問メモから項目抽出を使う。
- 初期版ではアプリ内録音機能は持たない。
- 初期版でAIが反映する項目は、主訴等と服薬指導内容だけにする。
- 副作用、残薬、服薬状況などは初期版ではAIで自動確定しない。

訪問メモ入力:

- 訪問メモ欄へ手入力または貼り付けで入力する。
- Windowsの音声入力（Win+H）などOS側の入力補助は利用可能とする。
- 入力した訪問メモは報告書保存時に保存する。

反映仕様:

- ローカルLLMで訪問メモから主訴等、服薬指導内容に振り分ける。
- 空欄なら該当欄へ直接入力する。
- 既存文がある場合は、追記/置換/キャンセルを選ばせる。
- 反映後は「AI反映済み」を一時表示する。
- 保存前に薬剤師が確認する。
- 元に戻せるようにする。

保存仕様:

- 訪問メモは報告書スナップショットとして保存する。
- 前回報告書コピー時は訪問メモを引き継がない。

エラー時:

- LLM抽出が失敗した場合は、分かりやすくエラーを表示する。
- 通常手入力に戻る。
- 入力済みデータは消さない。
- AI失敗で保存/印刷を止めない。
- 再試行は使用者が手動で行う。

## 18. AI環境セットアップ

- ローカルLLMはPC内で処理する。
- 初回のモデルダウンロードにはインターネットが必要。
- 薬局に戻ればWi-Fiがある前提で、モデルダウンロードを案内する。
- アプリがOllama、必要モデル、PC性能、空き容量を状態確認する。
- 長い訪問メモでは処理に時間がかかる可能性があるため、処理時間の目安を表示する。
- 不足しているものは、セットアップ画面で順番に案内してインストールさせる。
- AI未セットアップでも通常機能は使える。

## 19. Web入口とローカルアプリの接続案内

Vercel入口は初回導入、更新案内、ローカルアプリの接続確認に使う。日常利用の主導線はWindowsデスクトップショートカットとし、Vercel↔localhostブリッジは凍結機能として保守する。

- ローカルアプリは `127.0.0.1` の固定ポート候補でローカルHTTP APIを立てる。
- VercelページはローカルHTTP APIへ接続確認を行う。CORSはVercelドメインとlocalhostを標準許可し、独自ドメインを使う場合はローカルアプリ側の許可Originへ追加する。
- ポート競合に備え、複数のポート候補を順に試す。
- Vercel URLからローカルアプリ起動を促すため、Windowsインストール時にカスタムURIスキームを登録する。
- ローカルアプリ未インストール: Windows版インストールボタンを表示
- ローカルアプリ未起動: 起動手順を表示
- バージョンが古い: 更新ボタンを表示
- ローカルDB準備中: 待機表示
- AI未セットアップ: 通常機能は使えるが、AIセットアップ案内を表示
- 接続OK: 報告書作成へ進む

素人向け文言にし、エラーコードだけを表示しない。
