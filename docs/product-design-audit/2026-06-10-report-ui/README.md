# Product Design UI監査: 新規報告書作成画面

監査日: 2026-06-10
対象: `/reports/new` 新規報告書作成画面
保存先: `docs/product-design-audit/2026-06-10-report-ui/`

- Mac開発環境のローカルVite表示で確認。
- 外部Supabaseへの名前解決が失敗する環境のため、一覧画面ではなく新規作成画面を直接監査した。

- スクリーンショットから判断できる範囲のUX/デザイン/アクセシビリティ監査であり、実利用者テストやキーボード操作の完全検証は未実施。

## ステップ別評価

1. 空の新規報告書画面: 要改善
   - 良い点: 上部ナビ、セクション内のラベル、14/21/28日のクイック選択は分かりやすい。
   - 問題: 保存バーが画面中央付近の入力内容に重なって見え、状況確認セクションと標準処方日数の境界を遮る。
   - 問題: 空の基本情報が「様 (歳)」と表示され、未入力状態として少し不自然。
   - 問題: 主要セクションがすべて同じカード表現で、入力の優先順位が読み取りにくい。

2. 定期薬を1件追加: 概ね機能するが要整理
   - 良い点: 前回いつまで分、今回処方日数、実残日数、合計残日数、いつまで分が1行で確認できる。
   - 良い点: 実残日数の入力で合計残日数といつまで分が更新され、今回仕様の核は画面に出ている。
   - 問題: `+` だけの追加ボタンは意味が弱く、行追加のクリック領域としても目立たない。
   - 問題: 計算結果の入力欄が編集欄とほぼ同じ見た目で、ユーザーが編集できる欄と誤認しやすい。
   - 問題: `2026-07-15` と日付形式が画面内の `2026/06/14` と揃っていない。

3. 390px幅の定期薬入力: 破綻
   - 問題: 薬剤行のグリッドが狭幅でも横並びのままで、列見出しが縦書きのように折り返される。
   - 問題: 行の一部が画面外にはみ出し、保存バーも下部で操作領域を圧迫する。
   - 問題: 現場のMacデモが主でも、狭いブラウザ幅や分割表示で同じ崩れが起こり得る。

## アクセシビリティリスク

1. 追加ボタンが `+` のみで、スクリーンリーダーや初見ユーザーに目的が伝わりにくい。
2. カスタム選択UIの矢印ボタンが無名ボタンとして読まれる可能性がある。
3. 保存バーが内容を覆うため、ズーム表示や小さい画面では入力内容・フォーカス位置を隠すリスクがある。
4. 計算結果欄と編集欄の視覚差が弱く、入力可能性の affordance が曖昧。

## 修正優先度

### P0: 保存バーの重なりを解消

- フォーム下部に保存バー分の余白を確保する。
- 可能ならバーを画面幅いっぱいの白い帯ではなく、フォーム下の固定アクション領域として扱う。
- 監査証拠: `01-empty-form-desktop.png`

### P0: 薬剤入力のレスポンシブ設計を変更

- デスクトップでは表形式を維持。
- 960px未満では1薬剤1カードの縦積みに切り替える。
- 列見出しを無理に折り返さず、各入力のラベルを上に置く。
- 監査証拠: `03-mobile-regular-medication.png`

### P1: 薬剤追加ボタンを明示化

- `+` のみではなく `定期薬を追加` / `臨時薬を追加` のように表示する。
- lucideの `Plus` アイコンを併用する。
- 監査証拠: `01-empty-form-desktop.png`, `02-regular-medication-row.png`

### P1: 計算結果は入力欄ではなく読み取り専用表示へ

- `合計残日数` と `いつまで分` は淡い背景の数値チップまたは読み取り専用セルとして表示する。
- 日付表示は `YYYY/MM/DD` に統一する。
- 監査証拠: `02-regular-medication-row.png`

### P2: 空状態の基本情報表示を自然にする

- 患者未選択時は `基本情報` のみ、または `患者未選択` と表示する。
- `様 (歳)` は氏名と生年月日がある時だけ出す。
- 監査証拠: `01-empty-form-desktop.png`

## 実装方針

次の実装修正は、まず `MedicationListForm.tsx` と `ReportEdit.tsx` に限定するのがよい。

1. 保存バーとフォーム余白の調整。
2. 薬剤行のCSSクラス化と狭幅時カード化。
3. 追加ボタンの文言化。
4. 計算結果の見た目を読み取り専用表示へ変更。

帳票印刷側の見た目は今回のUI監査対象外。入力画面が落ち着いてから、A4 1枚での印刷再確認を別途行う。

## 実装済み

2026-06-10にP0/P1を実装。

1. 保存バーを画面下固定から通常の下部アクション領域へ変更し、入力欄を覆わないようにした。
2. 薬剤入力は960px未満で1薬剤1カードの縦積みに切り替えた。
3. `+` のみの追加ボタンを `定期薬を追加` / `臨時薬・その他を追加` に変更した。
4. `合計残日数` と `いつまで分` は入力欄ではなく読み取り専用表示に変更した。
5. 計算日付の表示を `YYYY/MM/DD` に統一した。
6. 患者未選択時の基本情報サマリーを `患者未選択` に変更した。
